## Before you submit — real open items

1. **Screenshots**: still need to come from a real device running the actual production build with real, populated data — the web-preview testing tool this session used is CORS-blocked from the API and would show empty/broken states, and there's no Android emulator/device available server-side. Once the production build is installed on a real phone, send screenshots of the key screens (Home, Today, Meal Plan, Nutrition, Price Comparison, AI Chat) and they can be reviewed/ordered before submission — stores weight the first 2-3 images most heavily.
2. **Age rating / content questionnaire**: both stores ask a standalone set of yes/no questions at submission time (violence, gambling, user-generated content, etc.) — answered live in each console, see the separate content-rating/data-safety draft answers doc for a starting point based on what the app actually does.
3. **In-app purchases are not live at initial submission** — no Play Console/App Store Connect subscription products exist yet, and the mobile app now shows a "Subscriptions launching soon" state on the Subscribe screen instead of a broken purchase flow (fixed 2026-09-23). Real subscriptions are a planned follow-up release, not a launch blocker — see `IAP_STORE_SETUP_CHECKLIST.md` for that separate checklist.
